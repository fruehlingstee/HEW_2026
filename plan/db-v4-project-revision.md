# 統合DB案v4に伴う企画改訂メモ

改訂日: 2026-10-27

会員登録と公開デザインのコピーを実装したいというユーザー指示に基づき、企画本文を更新した。これは追加機能の実装完了やチーム全員の承認を示すものではない。DBMLは設計提案であり、既存要件に必要な全カラム・制約を網羅する完成DDLではない。

## 改訂後の企画概要

CakeCanvasは、5号ケーキを3Dプレビューで自分好みに作成し、見積もり・予約・テスト決済・店頭受取まで行えるセミオーダーケーキサービスである。ゼロから作る方法に加え、他の利用者が公開した人気デザインを自分用にコピーしてアレンジできる。会員は保存デザイン・公開作品・お気に入り・注文履歴をマイページで管理し、同じ構成から再注文できる。

店舗は注文時に固定した構成と料金明細から、番号付き配置図と製造指示書を確認する。元デザインやプロフィールを後から変更しても、既存注文の内容・連絡先は変わらない。

## 旧方針からの変更

| 項目 | 従来 | 改訂後 |
|---|---|---|
| 購入者の認証 | ゲスト注文のみ | 会員登録を追加し、ゲスト注文も維持 |
| 会員機能 | 対象外 | メール確認、ログイン／ログアウト、再設定、プロフィール、マイページ、退会 |
| デザインの作り始め | 自分で色・飾りを指定 | 自作に加え、公開作品からコピーして編集 |
| 作品の公開 | 限定共有URLが中心 | 明示的なギャラリー公開と、限定共有を区別 |
| 人気・お気に入り | 未定義 | 公開版ごとに1会員1件のお気に入り。件数で人気順 |
| 注文後の編集 | 元デザインをロック | 注文の構成・価格を固定し、元デザインは再編集・再注文可能 |
| 店舗認証 | 店舗共通パスワード | 共通会員アカウント＋店舗所属・roleで本人単位に制御 |
| 注文者情報 | 注文本体に顧客情報 | 会員プロフィールと注文時連絡先を分離 |
| パーツ | 常に利用可能 | 新規利用の有効／無効を管理。在庫数は管理しない |
| 通知 | 注文関連4種類 | 注文通知にメール確認・パスワード再設定を追加 |
| 保持期間 | 未注文7日を一律適用 | 会員保存・ゲスト一時デザイン・公開版・注文を区別 |

## 維持する企画条件

- 1店舗・1注文1台の5号ケーキ・店頭受取を初期の提供範囲とする。
- 色指定、自由配置、外周デコ、メッセージ、見積もり、関連アレルゲン確認を提供する。
- 注文前の編集・注文手続きはPC。既存の注文受付後画面はPC・スマホ対応を維持する。
- 1台1製造ポイント、初期1日5ポイント、決済前15分の仮確保を維持する。
- Stripeテスト決済、Webhook確定、返金規定、番号付き俯瞰SVG・A4製造指示書を維持する。
- 価格・税・返金の数値は今回の企画改訂で変更しない。外部の税制・料金の最新確認を行ったものではなく、プロジェクト内のテスト仕様として扱う。
- 画像をサーバー保存しない方針を維持する。公開作品も構成データから描画する。
- 10月30日の3D判定と既存の性能目標を維持し、追加会員機能の完成を判定条件にしない。

## 利用者の流れ

### 自作から注文

1. 色・飾り・メッセージを編集する。
2. 会員は自分のデザインとして保存できる。ゲスト注文も可能。
3. 現在の店舗条件で金額・パーツ・配置・アレルゲン・受取枠を確認する。
4. 注文の構成・金額・連絡先を固定し、決済へ進む。
5. 決済成功通知で注文を確定し、会員履歴または秘密URLから照会する。

### 人気作品から注文

1. 同じ店舗の公開ギャラリーを新着順・人気順で見る。
2. 公開中かつコピー可の作品を選ぶ。
3. 通常の永続保存では確認済み有効会員として新しい自分のデザインへコピーする。
4. 色・飾り・文字を変更し、現在の条件で再見積もりする。
5. 自作と同じ注文経路へ進む。

### 自分の作品を公開

1. 作者が自分のデザインにタイトル・説明・公開用表示名を付ける。
2. 公開する文字や構成に実名等の個人情報がないか確認する。
3. コピー可否を設定し、公開時点の構成を固定保存する。
4. 元の編集デザインを更新しても公開版は変えない。変更版は新規公開版にする。
5. 非公開化後は新規閲覧・コピーを停止する。既存コピーや注文は削除しない。

## DB案v4の補完事項

DB案に列がないことだけを理由に既存の企画要件を廃止しない。次をPrismaモデル・実装契約の確定前に確認する。今回はDBMLそのものを変更していない。

| 項目 | 現状と補完すること |
|---|---|
| アレルゲン区分・店舗注記 | part_allergensにcontains_type、storesに店舗注記等がない。「含む／同一設備」の区別と表示・固定保存の形式を補完する |
| 受取日の受付条件 | storesに最短日数・受付上限日数・締切時刻がない。設定の保存先とJSTでの判定契約を補完する |
| 外周デコ・プレート・パレット | v4はパーツ種別・配置色・メッセージのみが中心。料金種別、ありなし、上限、未使用色、プレート有無の表現、保存時と復元時の対応を確定する |
| 返金の判断記録 | refundsに返金率や判定根拠の専用列がない。返金不可の申請をどこに残すかも含めて補完する |
| 手数料・店舗課金 | platform_fees / store_subscriptions相当が未収録。3%手数料の計算根拠・保存要否を確認し、店舗月額課金は将来案として別判断する |
| 所有権と同一店舗の整合 | 会員所有者・店舗所属・ゲスト編集権限、デザインとパーツ等の同一店舗を認可・複合FK・トランザクションで保証する |
| 状態・制約・期限 | varcharのstatus等の値、JSONのschema_version、明細・注文・返金合計、枠上限、保持期限処理を定義する |
| 公開の取り下げと退会 | 新規閲覧・コピーの停止、既存コピー保持、公開用表示名の匿名化、会員保存デザインの期限を決める |
| 新規画面の対象端末 | 会員登録・マイページ・ギャラリー等のスマホ対応範囲を決定。3D編集のスマホ対応を暗黙に追加しない |
